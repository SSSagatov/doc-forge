## 📋 Что понадобится

| Нужно | Пояснение |
| :--- | :--- |
| **Go 1.25 или новее** | Для запуска приложения. |
| **PostgreSQL** | Должен быть запущен на вашем компьютере или доступен на другом сервере. |
| **Данные для подключения** | Название существующей базы, имя пользователя и пароль. |
| **Интернет** | Для загрузки необходимых компонентов при первом запуске. |

**Make — по желанию.** 
Он позволяет использовать короткую команду 
`make run` - запуск приложения,
`make test` - тестирование БД, 
`make migrate` - запуск миграций.

## 🚀 Первый запуск

### 01 · Подготовьте проект

Откройте терминал в папке проекта — там, где находятся `go.mod` и `.env.example`.

Загрузите необходимые компоненты:

```sh
go mod download
```

> Все команды ниже выполняются в этой же папке.

### 02 · Создайте файл настроек

Скопируйте `.env.example` в новый файл с именем `.env`.

**Windows · PowerShell**

```powershell
Copy-Item .env.example .env
```

**Linux · macOS**

```sh
cp .env.example .env
```

Если `.env` уже есть, пропустите копирование и откройте его для редактирования.

### 03 · Укажите данные своей базы

Откройте `.env` в текстовом редакторе. Пример для PostgreSQL на вашем компьютере:

```dotenv
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=your_password
DB_NAME=postgres
DB_SSLMODE=disable
```

**Замените `your_password` своим паролем** и проверьте остальные значения:

| Настройка | Что указать |
| :--- | :--- |
| `DB_HOST` | `localhost` для базы на вашем компьютере. Для другой — адрес её сервера. |
| `DB_PORT` | Обычно `5432`. Меняйте, если для вашей базы указан другой порт. |
| `DB_USER` | Имя пользователя PostgreSQL. |
| `DB_PASSWORD` | Пароль этого пользователя. |
| `DB_NAME` | Название уже существующей базы данных. |
| `DB_SSLMODE` | `disable` для этого локального примера. Для удалённой базы уточните значение у её администратора. |

Сохраните `.env` — приложение прочитает настройки при запуске проверки.

### 04 · Проверьте подключение

```sh
go test -v -count=1 ./db -run TestDB
```

При успешном подключении появится сообщение:

```text
--- PASS: TestDB
```

> **✅ Подключение работает!**  
> После этого сообщения программа завершится. Проверка не меняет данные в базе.

<a id="commands"></a>

## ⚡ Команды под рукой

| Действие | Команда |
| :--- | :--- |
| Проверить подключение | `go test -v -count=1 ./db -run TestDB` |
| Та же проверка через Make | `make test` |
| Запустить все тесты | `go test -v -count=1 ./...` |

Команда `make run` пока завершает программу без сообщений. Проверка подключения запускается отдельно через `go test` или `make test`.

<a id="help"></a>

## 💬 Если что-то не получилось

<details>
<summary><strong>Команда go не найдена</strong></summary>

Убедитесь, что Go установлен. После установки закройте терминал и откройте его заново.

Проверить установленную версию можно так:

```sh
go version
```

</details>

<details>
<summary><strong>Не удаётся прочитать .env</strong></summary>

Если появилось сообщение `failed to load .env`:

- Проверьте, что файл называется `.env`, а не `.env.txt`.
- Убедитесь, что он находится в папке проекта и доступен для чтения.
- Запускайте команду из этой же папки.
- Сверьте строки настроек с примером выше.

</details>

<details>
<summary><strong>PostgreSQL отклоняет пароль</strong></summary>

Сообщение `password authentication failed` означает, что сервер отклонил данные для входа. Проверьте `DB_USER` и `DB_PASSWORD` в `.env`, сохраните файл и повторите проверку.

</details>

<details>
<summary><strong>База недоступна или не найдена</strong></summary>

При сообщении `connection refused` или долгом ожидании убедитесь, что PostgreSQL запущен, а `DB_HOST` и `DB_PORT` указаны правильно.

Если сообщение говорит, что база не существует, проверьте `DB_NAME`. Приложение подключается к готовой базе и не создаёт её автоматически.

</details>

<details>
<summary><strong>Make не находит команду test</strong></summary>

При ошибке `No rule to make target 'test'` откройте терминал в папке проекта и укажите файл явно:

```sh
make -f Makefile test
```

Можно также запустить проверку напрямую — Make для этого не нужен:

```sh
go test -v -count=1 ./db -run TestDB
```

</details>

<details>
<summary><strong>Программа закрылась без сообщения</strong></summary>

Запустите проверку отдельной командой:

```sh
go test -v -count=1 ./db -run TestDB
```

Параметр `-v` показывает результат проверки, а `-count=1` выполняет её заново при каждом запуске.

</details>
