# doc-forge

**Первый запуск — шаг за шагом**

> **Что доступно сейчас**  
> HTTP-сервер принимает PDF, отправляет его в Google Gemini и сохраняет документ, задание и результат анализа в PostgreSQL.

## Текущий функционал

- Веб-страница `GET /`: выбор одного PDF, автоматическая загрузка и отображение результата без перезагрузки страницы. Требуется JavaScript.
- Загрузка через `POST /doc/pdf/upload`: `multipart/form-data`, файловое поле `file`.
- Максимальный размер PDF — **10 МиБ (10 485 760 байт)**; всего тела запроса — 11 МиБ с учётом multipart-заголовков.
- Проверка расширения `.pdf` без учёта регистра и первых пяти байт `%PDF-`. Полный разбор содержимого PDF пока не выполняется.
- Сохранение в `uploads/` относительно рабочей директории. Каталог создаётся автоматически, файлы получают сгенерированные имена `document-*.pdf`; исходное имя не используется как путь.
- Graceful shutdown по `Ctrl+C` / `SIGTERM`: прекращение приёма соединений, до 30 секунд на активные запросы, затем принудительное закрытие. Повторный `Ctrl+C` завершает процесс немедленно.
- PostgreSQL: пул подключений `pgx`, проверка `Ping` с таймаутом 5 секунд и отдельный интеграционный тест.
- Мигратор применяет SQL-миграции вверх; начальная схема содержит таблицы `documents`, `jobs` и `analysis_results`.

- Gemini возвращает `summary` (строку), `requirements`, `entities`, `risks` (массивы строк). Результат выводится в браузере и записывается в `analysis_results`, включая сырой ответ и счётчики токенов.
- Анализ синхронный: HTTP-запрос ожидает результат до 120 секунд после сохранения файла. Документ получает статус `processing`, затем `completed` или `failed`; запись задания содержит время и число попыток.
- Создание документа/задания и сохранение результата/статуса выполняются отдельными транзакциями. При сбое анализа приложение пытается записать `failed` с отдельным таймаутом 5 секунд. Если БД недоступна или процесс аварийно завершён, запись может остаться `processing`; автоматического восстановления пока нет.

Фоновой очереди, автоматических повторов, авторизации, списка и скачивания файлов через HTTP пока нет. Повторная загрузка создаёт новый документ и задание. `Dockerfile` и `docker-compose.yaml` пока пустые.

## 📋 Что понадобится

| Нужно | Пояснение |
| :--- | :--- |
| **Go 1.25 или новее** | Для запуска приложения. |
| **PostgreSQL** | Нужен для работы сервера; перед первой загрузкой примените миграции. |
| **Gemini API key** | Укажите `API_KEY` в `.env`; PDF отправляется в Google для анализа. |
| **Данные для подключения** | Для работы с БД: название существующей базы, имя пользователя и пароль. |
| **Интернет** | Для загрузки зависимостей и запросов к Gemini. |

**Make — по желанию.** 
Он позволяет использовать короткую команду 
`make run` - запуск приложения,
`make test` - тестирование БД, 
Для миграций используйте команду из раздела ниже: текущая цель `make migrate` требует исправления относительных путей.

## 🚀 Первый запуск

### 01 · Подготовьте проект

Откройте терминал в папке проекта — там, где находятся `go.mod` и `.env.example`.

Загрузите необходимые компоненты:

```sh
go mod download
```

> Все команды ниже выполняются в этой же папке.

### 02 · Запустите веб-сервис

Перед первым запуском выполните шаги 03–06 ниже: заполните `.env` и примените миграции.

```sh
go run ./api-service/cmd
```

Или выполните `make run`. Откройте http://localhost:8080, нажмите кнопку загрузки и выберите PDF до 10 МиБ. Файл появится в `uploads/` в корне проекта.

Сервер слушает только `127.0.0.1:8080` и продолжает работать до остановки через `Ctrl+C`. Таймаут чтения заголовков — 5 секунд; чтения и простоя — 60 секунд; записи ответа — 180 секунд.

Для проверки API из терминала:

```sh
curl -F "file=@document.pdf" http://localhost:8080/doc/pdf/upload
```

В Windows PowerShell используйте `curl.exe` вместо `curl`.

Ответ имеет формат JSON с полями `message` и `data`. В успешном ответе `data.document`, `data.job`, `data.analysis` содержат сохранённые сущности. HTTP-коды:

| Код | Значение |
| :--- | :--- |
| `201` | PDF проанализирован, результат сохранён. |
| `400` | Некорректная форма, отсутствует файл или передано несколько файлов. |
| `413` | Превышен размер файла или запроса. |
| `415` | Неподдерживаемое расширение или отсутствует сигнатура PDF. |
| `500` | Ошибка чтения/сохранения файла или создания записей в БД. |
| `502` | Не удалось завершить анализ или сохранить его результат. При созданном задании PDF сохраняется для диагностики. |

Следующие шаги обязательны для запуска анализа.

### 03 · Создайте файл настроек

Скопируйте `.env.example` в новый файл с именем `.env`.

**Windows · PowerShell**

```powershell
Copy-Item .env.example .env
```

**Linux · macOS**

```sh
cp .env.example .env
```

Если `.env` уже есть, пропустите копирование и откройте его для редактирования.

### 04 · Укажите данные своей базы

Откройте `.env` в текстовом редакторе. Пример для PostgreSQL на вашем компьютере:

```dotenv
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=your_password
DB_NAME=postgres
DB_SSLMODE=disable
API_KEY=your_google_gemini_api_key
MODEL=gemini-2.5-flash
RESPONSE_FORMAT=json_object
```

**Замените `your_password` своим паролем** и проверьте остальные значения:

| Настройка | Что указать |
| :--- | :--- |
| `DB_HOST` | `localhost` для базы на вашем компьютере. Для другой — адрес её сервера. |
| `DB_PORT` | Обычно `5432`. Меняйте, если для вашей базы указан другой порт. |
| `DB_USER` | Имя пользователя PostgreSQL. |
| `DB_PASSWORD` | Пароль этого пользователя. |
| `DB_NAME` | Название уже существующей базы данных. |
| `DB_SSLMODE` | `disable` для этого локального примера. Для удалённой базы уточните значение у её администратора. |

Сохраните `.env` — приложение читает его при старте. Переменные процесса имеют приоритет. Файл ищется в рабочем каталоге и выше; путь можно задать явно через `ENV_FILE`.

Клиент использует нативный Gemini `generateContent`, PDF передаётся как inline-данные, ответ ограничен JSON-схемой. `FORMAT=openai`, если остался в `.env`, не используется. `RESPONSE_FORMAT` поддерживает `json_object` и `application/json`. Квоты и доступность модели зависят от Google-проекта; HTTP 429 может означать исчерпанную квоту. Ключ остаётся на сервере. См. [документацию Gemini для PDF](https://ai.google.dev/gemini-api/docs/generate-content/document-processing).

### 05 · Проверьте подключение

```sh
go test -v -count=1 ./api-service/database/postgres -run '^TestDB$'
```

При успешном подключении появится сообщение:

```text
--- PASS: TestDB
```

> **✅ Подключение работает!**  
> Тест завершится. Проверка не меняет данные в базе и не запускает HTTP-сервис.

### 06 · Примените миграции

Из корня проекта:

```sh
go run ./api-service/cmd/migrator -path api-service/migrations
```

Параметр `-path` указывает каталог миграций относительно рабочей директории. Текущая команда `make migrate` из корня не передаёт этот путь — используйте команду выше.

Миграции создают таблицы в существующей базе. Если новых миграций нет, команда сообщает `Database is up to date; no migrations to apply`. CLI пока поддерживает только применение миграций, без команды отката.

## ⚡ Команды под рукой

| Действие | Команда |
| :--- | :--- |
| Запустить HTTP-сервис | `go run ./api-service/cmd` или `make run` |
| Проверить обработчики загрузки без БД | `go test -v -count=1 ./api-service/controllers` |
| Проверить подключение | `go test -v -count=1 ./api-service/database/postgres -run '^TestDB$'` |
| Та же проверка через Make | `make test` |
| Запустить все тесты | `go test -v -count=1 ./...` |
| Тесты без живой БД и Gemini | `go test ./api-service/... -skip '^TestDB$'` |

Все тесты включают интеграционный `TestDB`, поэтому для `go test ./...` нужны настроенный `.env` и доступный PostgreSQL. Тесты обработчиков проверяют маршруты, сохранение PDF, неверный формат и превышение размера.

## 💬 Если что-то не получилось

<details>
<summary><strong>Команда go не найдена</strong></summary>

Убедитесь, что Go установлен. После установки закройте терминал и откройте его заново.

Проверить установленную версию можно так:

```sh
go version
```

</details>

<details>
<summary><strong>Не удаётся прочитать .env</strong></summary>

Если появилось сообщение `failed to load .env`:

- Проверьте, что файл называется `.env`, а не `.env.txt`.
- Убедитесь, что он находится в папке проекта и доступен для чтения.
- Файл ищется в текущем и родительских каталогах; при необходимости укажите его путь через `ENV_FILE`.
- Сверьте строки настроек с примером выше.

</details>

<details>
<summary><strong>PostgreSQL отклоняет пароль</strong></summary>

Сообщение `password authentication failed` означает, что сервер отклонил данные для входа. Проверьте `DB_USER` и `DB_PASSWORD` в `.env`, сохраните файл и повторите проверку.

</details>

<details>
<summary><strong>База недоступна или не найдена</strong></summary>

При сообщении `connection refused` или долгом ожидании убедитесь, что PostgreSQL запущен, а `DB_HOST` и `DB_PORT` указаны правильно.

Если сообщение говорит, что база не существует, проверьте `DB_NAME`. Приложение подключается к готовой базе и не создаёт её автоматически.

</details>

<details>
<summary><strong>Make не находит команду test</strong></summary>

При ошибке `No rule to make target 'test'` откройте терминал в папке проекта и укажите файл явно:

```sh
make -f Makefile test
```

Можно также запустить проверку напрямую — Make для этого не нужен:

```sh
go test -v -count=1 ./api-service/database/postgres -run '^TestDB$'
```

</details>

<details>
<summary><strong>Как отдельно проверить БД</strong></summary>

Запустите проверку отдельной командой:

```sh
go test -v -count=1 ./api-service/database/postgres -run '^TestDB$'
```

Параметр `-v` показывает результат проверки, а `-count=1` выполняет её заново при каждом запуске.

</details>
